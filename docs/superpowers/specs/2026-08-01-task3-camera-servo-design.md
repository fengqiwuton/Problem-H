# 第三问摄像机与舵机协同控制设计

## 目标

小车保持静止，小钢球从水管中心 O 点出发。按下 PB1 后，控制器先使小球到达 `+5 cm`，随后折返至 `-5 cm` 并稳定。完整过程不超过 `5 s`，两个目标位置的绝对误差不超过 `1 cm`。

第三问使用独立固件入口。`user/main.c` 通过编译期常量默认选择第三问入口，生成的固件只初始化并周期调用第三问模块，不运行循迹控制。现有第二问入口代码保留在未启用的编译分支中，避免覆盖并行进行的循迹优化；任务之间不进行运行时切换。

## 硬件边界

- OpenMV 检测小球位置，以水管中心为零点，通过 `$B,<mm>#` 发送整数毫米；丢球发送 `$L#`。
- STM32 使用 PA4 软件串口接收 OpenMV，避免占用 USART3。
- SC09/SCS 舵机由 USART3 半双工总线控制，舵机 ID 为 1。
- PB1 为启动/重新准备按键。
- 车轮电机在初始化后始终保持停止。
- 舵机位置限制在 `BOARD_BALANCE_SERVO_SAFE_MIN` 至 `BOARD_BALANCE_SERVO_SAFE_MAX`。

旧的 `camera.c`、`ball_balance.c`、`task3_openloop.c` 和 `task3_asym_move.c` 不参与第三问运行，避免串口冲突和多套控制逻辑同时生效。

## 主程序

`main.c` 的第三问编译分支完成以下工作：

1. 初始化调试串口、OLED、按键和第三问控制模块。
2. 将所有车轮电机停止。
3. 以固定 `10 ms` 周期调用 `task3_update()`。
4. 按下 PB1 时调用 `task3_start()`；运行中再次按下则回到安全准备状态。
5. OLED 约每 `100 ms` 更新一次。
6. 调试串口约每 `100 ms` 输出一次状态、时间、位置、速度、目标和舵机命令。

## 控制状态机

状态流转如下：

`WAIT_CAMERA -> CENTER_READY -> GO_PLUS -> GO_MINUS -> HOLD_MINUS`

异常状态为 `CAMERA_LOST` 和 `TIMEOUT`。

### WAIT_CAMERA

等待连续有效的摄像机位置。舵机保持标定中位，车轮电机停止。

### CENTER_READY

要求小球位于中心附近且速度较低，并连续稳定约 `300 ms`。满足后允许 PB1 启动；不满足时 OLED 和串口显示当前位置，提示重新放置小球。

若用户在摄像机尚未准备好时按下 PB1，控制器记住启动请求，在中心条件满足后自动开始，避免必须重复按键。

### GO_PLUS

目标位置为 `+500` 个 `0.1 mm`。位置闭环计算误差，速度反馈提供阻尼。只有实测位置进入 `+400` 至 `+600` 个 `0.1 mm` 的合格区后，才允许切换到负向目标。

速度反馈在接近正向目标时提前减小倾角。进入合格区后立即切换为负向制动，尽量保证正向峰值不超过 `+600` 个 `0.1 mm`，无需在正向目标长时间停稳。

### GO_MINUS

目标位置为 `-500` 个 `0.1 mm`。当位置持续处于 `-600` 至 `-400` 个 `0.1 mm`、速度绝对值低于设定阈值且保持至少 `300 ms` 时，进入最终保持状态。

### HOLD_MINUS

继续闭环保持 `-5 cm`，而不是将舵机直接回中。记录完成时间和最终误差，等待复位或重新启动。

### CAMERA_LOST 和 TIMEOUT

单个 `$L#` 或单次异常帧不会立刻终止。连续约 `150 ms` 没有可信位置后进入 `CAMERA_LOST`，舵机平滑回到标定中位。

运行时间达到 `4.8 s` 仍未进入 `HOLD_MINUS` 时进入 `TIMEOUT`，为题目 `5 s` 上限保留执行和显示余量。

## 位置与速度处理

- 只接受位于水管物理范围内的位置。
- 对不符合最大位移/最大速度约束的单帧跳变进行拒绝，不让反光误检直接驱动舵机。
- 有效位置使用轻量低通滤波，避免增加明显延迟。
- 速度由相邻有效位置和真实帧间隔计算，再低通滤波并限幅。
- 滤波器在首次定位、重新捕获和重新启动时复位，避免旧速度残留。
- 控制周期与摄像机帧周期解耦；没有新帧时保持上一可信估计，不重复计算虚假速度。

## 舵机控制

采用位置误差与速度反馈组成的 PD 控制：

`servo = neutral + sign * (Kp * position_error - Kd * ball_velocity)`

- `neutral` 使用现场标定后的平衡位置。
- `sign` 独立配置，现场只需确认舵机增大位置是否使小球向正方向运动。
- 命令经过安全限幅和每周期变化率限制。
- 控制参数、稳定阈值、超时、舵机方向和中位集中定义，方便现场逐项标定。
- 不加入积分项，避免短时任务中的积分饱和和折返过冲。

## 可观测性

OLED 显示当前状态、球位置、目标位置、速度、舵机命令、摄像机有效性和运行时间。

UART1 使用 115200 波特率，输出固定格式的单行调试数据，便于记录；UART2 只保留给车轮电机驱动：

`T3,state=<n>,t=<ms>,x=<0.1mm>,v=<0.1mm/s>,target=<0.1mm>,servo=<pos>,cam=<0|1>`

OpenMV 画面继续框选亮色水管和小球，并在终端打印帧率与坐标；STM32 调试串口不与 OpenMV 或舵机串口共用。

## 验证

主机侧测试使用模拟摄像机帧和模拟舵机输出，验证：

- 未检测到摄像机或小球不在中心时不能启动。
- 提前按下 PB1 后，中心稳定时能够自动开始。
- 未实际进入正向合格区时不能折返。
- 到达正向合格区后切换到负向目标。
- 负向位置和速度连续满足条件后进入保持。
- 单帧丢失不会中止，持续丢失会安全回中。
- 超过 `4.8 s` 会进入超时状态。
- 舵机命令不会超过安全范围，单周期变化不会超过限制。

工程验证包括完整编译、串口协议检查和实机分阶段调试。实机先确认舵机方向与平衡中位，再分别验证中心等待、正向到达、负向稳定，最后记录至少五次完整运行的总时间、正向峰值和负向稳态误差。

## 验收标准

- PB1 一次启动，状态按预期完成，不需要人工干预。
- 小球实测进入 `+4 cm` 至 `+6 cm` 后折返。
- 最终稳定在 `-4 cm` 至 `-6 cm`，连续保持至少 `300 ms`。
- 从启动到进入最终保持不超过 `4.8 s`。
- 短暂误检或单帧丢失不会造成舵机突跳。
- 摄像机持续丢失或控制超时后舵机安全回中。
